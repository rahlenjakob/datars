Why it exists

No chart library runs on every screen. This one does.

D3 draws in a browser, Swift Charts on Apple's platforms, Android has no charts built in, and video and print mean redrawing by hand — so a chart that matters is built once per screen, and the copies drift apart. datars is one Rust engine, native in every host. Step it: the web chart morphs live on this page, beside what the iOS app, the desktop viewer and the CLI drew.

Bars, on six targets.

All six at the iPhone 16 Pro's chart box, 402 × 812, scaled to fit; the iOS capture is the screen under the status bar, its home indicator drawn by the system; the Android one is the sample app's view on an Android 15 emulator. No phone app has run on a physical device yet.

Big data, 60 fps

Four million stars. {{size:galaxy}} to start.

A synthetic barred spiral: every dot is one star of four million, and you can zoom from the whole galaxy down to a single one. The engine indexes the rows once into a pyramid of tiles; each frame draws only what the camera shows — a sample that keeps the galaxy's density from afar, every star up close. Camera tours run at 59–60 fps in Chrome. Drag to pan, scroll or pinch to zoom, hover a star — or take the tour.

Indexed once

The rows go into a quadtree whose levels are seeded samples of the data. Panning and zooming never re-read a row: tiles come and go, and a tile's stars are drawn from its cache.

Only what you see

The publish step ships the pyramid as an archive the page reads by byte range, from any static host. The first view needs a few hundred kilobytes; each zoom fetches the tiles it shows, and nothing else.

Sampled, never guessed

Every dot is a real row. A far-away view draws a uniform share of the stars — dense stays dense, sparse stays sparse — and the deeper levels fade in as you zoom until every one is there.

Each is a published chart this page drives through <datars-view>'s public API, and what the chart reports is printed beside it as you go. In an iOS or Android app the gestures are the same: the engine handles them, the host only forwards the pointer.

Drag through the year

The slider is drawn by the engine, not the page. Each bar's length is computed from it — the sunrise equation over each place's latitude, in the document's table — and the bars re-rank by key as you drag: Longyearbyen's midnight sun becomes polar night.

Write it once

A chart is a few lines of TypeScript

Change a number, rename a region or pick another recipe: the chart beside the code is a published chart, playing your edit as you type. Every mark keeps its key, so an edit is a morph, not a redraw. Then the same document goes everywhere, one line per host.

sales/doc.ts 
import { doc, data } from "@datars/sdk";
import { plot, bar } from "@datars/std";

export default doc({
  title: "Sales by region",
  data: { sales: data.values({
    region: ["", "", "", ""],
    sales:  [, , , ],
  }, { key: "region" }) },
  scene: plot({ data: "sales", x: "region", y: "sales",
    children: [bar({ labels: true })] }),
});

Get started

From a template to a published chart in four commands

datars isn't on npm or crates.io yet: you build the CLI from the repository, and the guide walks you through it — about fifteen minutes, most of it the first build.

  1. 1 Start from a template

    datars new sales --template story

    A complete, working sales/doc.ts.

  2. 2 Preview it live

    datars dev sales/doc.ts

    A page that morphs each save in, at phone widths and in dark mode, and explains any mark you click.

  3. 3 Check it

    datars lint sales/doc.ts

    Colliding labels, low contrast, unstable keys — with fixes.

  4. 4 Publish anywhere static

    datars publish sales/doc.ts \
  --alias sales --to site/

    A manifest and immutable chunks, for any bucket, CDN or Pages; embed it as above.
