For developers and agents

Tools that answer “why does it look like that?”

A datars chart is a TypeScript document, so your editor type-checks it and your agent can write it. Everything that makes it look the way it does can be asked: which data row an element came from, every expression and its value, what's wrong with it and how to fix it. Below is a chart with three deliberate mistakes, running live. Lint it, fix it, then click any mark and ask it why.

The live page

datars dev: all of it, on every save

A page with the chart, its states, its diagnostics and lint findings, rebuilt when the document or a local recipe changes — and it morphs from what's on screen to the new version, so you see what your edit changed. Click a mark and it explains it; switch to a phone width or dark mode from the toolbar; open Profile for what each frame and transition costs.

datars new mychart --template story   # chart | story | explorable | map
datars dev mychart/doc.ts             # live page: every save morphs in
datars publish mychart/doc.ts --alias sales --to site/

For coding agents

The same tools over MCP, the whole API on one page

datars-mcp speaks the Model Context Protocol over stdio. An agent can profile a data file, write a document, check it, render its states and look at the images, film its transitions, lint it and publish it — the loop a person uses, with structured results. llms.txt gives it the whole API on one page; the document format has a JSON Schema.

Every command

A CLI for the whole life of a chart

Look

render (PNG, SVG, PDF) · film (filmstrip + motion trails) · video (MP4 + captions) · inspect (the scene as text) · semantics (the accessibility tree) · states

Check

check (diagnostics, fonts with no source) · lint (identity, encoding, legibility, accessibility, theme) · explain · diff (what changes between states or versions) · test (goldens and motion sweeps)

Data and design

data profile (types, gaps, ranges, candidate keys, hints) · describe (a recipe's parameters) · eject · theme --specimen · fonts · new

Ship

publish · serve (static delivery, Range requests, an image server) · bundle and bundle inspect · basemap (automatic basemaps) · migrate

Measure

profile (cold and warm resolves, every transition stepped at 60 fps: stall, engine and raster per frame) · budgets · replay (a recorded session, exactly)

Fits your stack

TypeScript in, static files out

Typed documents

@datars/sdk builds documents; @datars/std is the chart library. Parameters are typed, misspelt ones get a “did you mean”, and lambdas compile to engine expressions — d => d.share * 2.

React, Vite and Next.js

React apps get a script-free path: a component, a Vite plugin and a Next.js config helper, with project templates. The guide →

Tested like code

datars test snapshots every example state and 64 frames of every transition, and checks motion invariants. Renders are deterministic, so a golden is a hash, and the same goldens check wasm, iOS and Android.
