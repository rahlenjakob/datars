Features

Everything a chart needs, from one document

datars is an engine and a standard library. You describe a chart — its data, its marks, its states — and the engine does the rest on every platform: layout, text, motion, interaction, accessibility, delivery. Below, each part in a few seconds: twelve live charts on the real engine, playing one at a time while they're on screen. Point at one to play it; follow it for the whole story.

Batteries included

Ready-made recipes: bars to sankeys, maps to cards

bar() → pie() → treemap(), keyed by drink

Data from anywhere

In the bundle, from your API, live, from the app, generated

view.provideData("feed", rows)

Your brand

Tokens, fonts, light, dark and high contrast — at runtime

view.setTokens({ … })

Big data, 60 fps

Four million points, streamed by the tile, drawn by the GPU

60,000 rows · 9,000 drawn a frame

Every platform

Web, iOS, Android, desktop, video, PNG, SVG and PDF

one document · phone, tablet, laptop

Maps, no tile server

Animation included

Every change morphs, by key — stories steer themselves

Interactive

Hover, click, brush, drag and zoom — linked views without glue code

Accessible

Screen readers, keyboard, reduced motion, text alternatives

Bikes rented by weekday, bar chart

Extendable

Recipes are TypeScript: eject one, or draw a scene of your own

geom.arc() petals → std bar()

Charts are content

Publish to any static host; republish, every embed updates

datars publish doc.ts --alias count

For developers and agents

Live page, lint, explain, film, profile, MCP, llms.txt

plot({ …, children: [bar()] })

Each card is a published chart, driven by this page through the public <datars-view> API — send(), setSignal(), setTokens(), provideData(). A chart draws only while it changes.
