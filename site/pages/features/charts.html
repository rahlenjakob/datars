Draw your own numbers this way

The example. Paste two columns — names, then numbers — from a spreadsheet or a CSV.

Your rows go into the published chart with view.provideData("visits", …) — no recipe code runs. They're checked first (2–24 rows, each name once, no negative numbers); anything else is refused and the chart keeps what it shows. The waffle and the parliament count percentage points of the total.

Under every recipe

The primitives they're made of — the same ones you get

The engine knows no bar charts. It knows keyed shapes, text, repeats, instances, groups, scales, table operations, signals, views and motion — and the standard library builds all 88 recipes from them with the public SDK, no private hooks. A plot is a recipe that declares scales and draws axis and grid around its marks; a bar is a repeat of keyed rectangles. When no recipe fits, write your own from the same parts, or copy one with datars eject.

Shapes and geometry

Rectangles, circles, arcs, paths, symbols and map features, each a shape with an ink and a key.

shape(geom.rect({ x, y, w, h, r: 4 }), { fill: "$accent" })
In the SDK reference →

Text

Shaped and measured by the engine with the chart's fonts — the same width on every platform — aligned, wrapped, haloed, counting when it's a number.

text(e("d.name"), [x, y], { style: { align: "end" } })
In the SDK reference →

Repeat

A template per row, per group, per tick or per legend entry. The engine evaluates it for every row; a recipe never sees the rows.

repeat("sales", shape(geom.circle({ … })))
In the SDK reference →

Instances

Thousands to millions of marks in one node and one draw, keyed like any other — how a parliament's seats and a waffle's squares are drawn.

instances({ from: "units", x: e("d.x"), y: e("d.y"), r: 4 })
In the SDK reference →

Groups and layout

Stacks, rows, columns, grids and flows, sized in px, shares or content — and columns that wrap into rows on a phone.

group({ layout: { type: "columns", gap: 12, wrap: 420 } })
In the SDK reference →

Scales

Band, point, linear, log, time, colour — declared on a group, read in any expression below it. A plot's axes are drawn from them.

scales: { x: { type: "band", domain: { data, field }, range: "width" } }
In the SDK reference →

Table operations

Stack, bin, window, pack, treemap, pie, sankey, waffle, parliament — layouts computed in Rust from the rows, not in your code.

op.stack({ x: "town", series: "mode", value: "k" })
In the SDK reference →

Signals and intents

Brushes, picks, drags and controls write signals; anything can read them — a filter, a highlight, a camera.

on: { brush: brush("range") }
In the SDK reference →

Views and cameras

Content in its own units, framed by a camera that fits a box, keys or a lon/lat area — and flies between them.

view({ camera: { fit: { keys: "=focus" } } })
In the SDK reference →

Motion

Keys pair marks across states; rules choose easing, routes, staggers and ghosts. Every transition on this page is planned from these.

motion({ select: { role: "datum" }, matcher: "by-key" })

What every recipe does for you

Defaults that hold up in print

Text that fits

Labels are measured with the chart's own fonts, by the engine, on every platform. Value labels sit above their bar, move inside when there's no room above, and are left out where they would be wider than the bar; legends flow into rows by their labels' widths. datars lint reports labels that collide or are cut off at the canvas edge.

Scales from the data

A plot builds its x, y and colour scales from the columns you name — band, linear, time, log — with nice ticks, number formats and axes sized to their labels. Marks inside it inherit the data and encodings.

Themed, never hard-coded

Recipes ask for tokens — $accent, $categorical[2], size.label, radius.bar — not colours. Your brand, dark mode and high contrast apply to all of them, including charts already published. Theming →

Motion built in

Bars grow from their baseline, lines draw on, slices and tiles morph by key, units split out of bars and merge back. Override any of it per state with motion rules. Animation →

Accessible by default

Every data mark carries a role, a label (“Sweden Democrats: 20.5”) and a value, so screen readers and text alternatives describe the data, not a picture. Accessibility →

Described for people and agents

Every parameter is typed and documented in the recipe itself: datars describe std/bar prints them, the chart reference is generated from them, and a misspelt setting comes back with “did you mean”.
