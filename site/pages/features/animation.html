Animation included

Every change animates — by key, with no animation code

Marks in datars carry the key of their data row. When anything changes — a story step, a filter, new data, an edit to the document — the engine matches old marks to new ones by key and plans the motion: shapes morph, a bar splits into its units, a country lifts off the map into its bar, text counts up. You describe states; the motion comes with them, for built-in charts and your own scenes alike.

Live · one motion rule

One dataset, many shapes

Bars → treemap → waffle → dots. Every party keeps its key, so each change of chart type is one keyed transition: rectangles become tiles, tiles split into a hundred squares, squares become dots, and back. The whole motion spec is one line.

motion: motion({ select: { role: "datum" }, matcher: "by-key", duration: 1.1 }),
program: story({ steps: ["bars", "treemap", "waffle", "dots"]
  .map((s) => step(s, { set: { shape: s } })) }),

Motion rules

Defaults that look right, rules when you want more

Recipes bring sensible motion: bars grow from their baseline, lines draw on, slices and tiles morph. Rules override any of it — for a role, a key path, or a pair of states — as data, not callbacks.

motion: motion(
  // Everything: 2.2 s, eased.
  { duration: 2.2, easing: "cubic-in-out", matcher: "by-path" },
  // Globe → orbits: data marks spiral out, rippling from the centre.
  { when: { from: "globe", to: "orbits" }, select: { role: "datum" },
    route: route.spiral(0.35), choreo: choreo.ripple(0.55) },
  // Orbits → spiral: arcs, the biggest last.
  { when: { from: "orbits", to: "spiral" }, select: { role: "datum" },
    route: route.arc(0.3), choreo: choreo.stagger("value", 0.5) },
  // Entering lines draw on; exiting ones draw off.
  { select: { kind: "polyline" }, enter: { trim: 0 }, exit: { trim: 0 } },
),

Matchers — who becomes whom

by-key pairs marks by their data key across different charts; by-path by their place in the scene; nearest by position; a hierarchy matcher splits one mark into its children — a bar into its seats — and merges them back.

Choreography — when each moves

together, stagger by data order, position, value or a seeded shuffle, phased exits–updates–enters, a wave across the screen, a ripple from a point.

Routes — the path they take

straight, arc, elbow, spiral, explode, hop, drift, drop with a bounce. Easings from cubic-in-out to cubic-bezier(…), spring(170, 26) and steps(4).

Enter and exit

Fade, grow from an origin, come from the parent, slide in, or draw on along the shape's length.

Stories steer themselves

A story is a list of states

A step sets signals; marks read them. The same program can be stepped with buttons and arrow keys, scrubbed by the page's scroll, triggered by scroll steps, or played on a timer — and the camera flies, the marks morph and the narration updates without a line of animation code.

Scroll stories

<datars-view steps=".step"> advances as your page's step elements scroll into view; scrub ties the position in the story to the scroll position, exactly — any frame of any transition.

Live data animates too

A live source re-requests on schedule; each snapshot animates into place — keyed bars move to their new ranks on election night.

Edits animate

In datars dev, saving the document morphs the chart from what's on screen to the new version, so you see what changed.

Motion you can trust

Seekable, testable, and polite

Pure functions of time

A frame is a function of the plan and the time, so a transition can be scrubbed, rendered frame-exactly to video, and drawn as a filmstrip with motion trails by datars film.

Tested frame by frame

datars test samples 64 frames of every transition of every example against goldens, and checks invariants: no flash, no blink, no pop, no NaN, exact endpoints.

Reduced motion

When the reader asks for less motion — on the web, iOS or Android — transitions become short crossfades, and autoplay and ambient clocks pause.
