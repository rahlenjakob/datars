Every platform

One document. Every screen. The same pixels.

Most chart libraries live in a browser; in an app they arrive as a web view or a screenshot. datars is one Rust engine that runs natively in each host — shaping the same fonts, laying out, animating and drawing — so a chart is the same chart everywhere. Don't take our word for it: below, one chart as the web runtime draws it live on this page, as the iOS and Android sample apps drew it in the simulator and the emulator, as the desktop viewer drew it, and as the CLI exported it to PNG, SVG, PDF and video. Proved, not promised

Cross-platform sameness is a test, not a hope

Text shaping, layout, motion and rasterization all happen in one deterministic engine with its own maths library and no randomly ordered hash maps, so floating point can't drift between platforms. Two checks hold it there.

The same hash on five targets

Every example state has a golden: a hash of its scene and of its CPU pixels, written by datars test on any machine. The same files check macOS on arm64 and x86-64, wasm in Node, the iOS simulator (DatarsKit's DeterminismTests) and an Android arm64 emulator (scripts/test-android.sh). The votes example's:

The hosts

Native in each, a few lines to embed

Apps install the runtime once; charts then arrive as bundles, like images, and update without an app release (charts are content).

  • iOS and macOS

    DatarsKit, a Swift package: a SwiftUI view, a UIKit/AppKit view, and the engine underneath. The story can follow your SwiftUI state; the user's own rows fill the chart's data slots on the device.

    import DatarsKit

DatarsChart(source: .url(chartURL),   // a published chart, or a .datars file in the app
            state: step,              // program state from SwiftUI
            data: ["spending": rows]) // the user's rows, never uploaded

    iOS 15+, macOS 12+ · frames drawn with Metal (the CPU reference where there's no GPU) · VoiceOver: per-item frames, adjustable sliders, activatable marks · Reduce Motion honoured · verified in the iOS simulator and on macOS

  • Android

    An AAR with a Kotlin DatarsView: load a published chart by URL or a .datars file from your assets, hand in the user's rows, drive the story from your UI. Use it from Compose through AndroidView.

    val chart = DatarsView(context)
chart.load("https://charts.example.com/c/spending")
chart.provideData("spending", rowsJson)  // stays on the phone
chart.setOnClickListener { chart.send("next") }

    minSdk 24 · arm64-v8a, x86_64 · frames drawn with Vulkan or GLES (the CPU reference where there's no GPU) · TalkBack through an accessibility node provider · “Remove animations” honoured · runs on the emulator; not yet tested on a physical device

  • Web

    One custom element, <datars-view>, in any page, CMS or framework. WebGPU where the browser has it, WebGL2 where it doesn't (Safari before iOS 26), the CPU renderer as the last resort; an ARIA mirror for screen readers; sleeps off screen.

    <script type="module" src="/runtime/datars.js"></script>
<datars-view src="https://charts.example.com/c/spending"></datars-view>

    {{runtime}} runtime, cached once per site · every chart on this site · React, Vite and Next.js: script-free setup

  • Desktop

    A native window for a document, a bundle, or a published chart by URL — the same bundle web pages and apps play. Arrow keys step the story; drag and wheel explore maps.

    datars-view https://charts.example.com/c/descent
datars-view doc.json --screenshot out.png --state 2

    wgpu: Metal, Vulkan, DX12 · accessibility tree through AccessKit (not yet exercised with a real screen reader)

  • Video

    Frame-exact MP4 of the whole story, rendered by the engine rather than recorded from a screen, with WebVTT captions from the narration. Change --size for 9:16, 1:1 or 16:9 — the chart re-lays itself out, so a vertical video is the phone layout, not a crop.

    datars video story.ts --size 360x640 --dpr 3   # 1080×1920
datars video story.ts --size 640x360 --dpr 3   # 1920×1080

    H.264 through ffmpeg · any frame rate · deterministic: the same file every time

  • Print and images

    PNG, SVG and vector PDF of any state. SVG and PDF keep text as text — searchable and accessible — and the PDF is one vector page with layers as transparency groups. datars serve renders them on request for social cards.

    datars render chart.ts --state 2 --out chart.pdf
curl "localhost:8787/render/chart.png?state=1&width=1200&height=630"

    PNG from the bit-exact CPU reference · no browser, no GPU needed · runs on a server or in CI

Made when this site was built

Any aspect ratio, as a film

datars video renders the program frame by frame from the engine's plan — not a screen recording — with WebVTT captions from the narration. Change --size and the chart lays itself out again: a vertical film is the phone layout, not a crop. Both films play live elsewhere on this site.

Install once

Charts arrive like images, not like code

App stores don't let apps download native code — and a datars chart isn't code. Published variants are data: scenes, plans, tables, geometry and bytecode for the engine's own expression interpreter. An app can refuse the one variant that carries sandboxed script and still get pre-expanded charts.

Update without a release

Republish and the app shows the new chart on its next load. Roll back by moving the alias back.

Offline first

Ship a .datars file in the app bundle for the first run; downloaded chunks are cached by content hash.

Private data stays private

A chart can declare a data slot; the app fills it with the signed-in user's rows on the device. One chart design for every user, nothing uploaded.
