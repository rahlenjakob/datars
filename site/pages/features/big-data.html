Big data, 60 fps

Millions of points, still sixty frames a second

datars draws big data the way maps draw the planet: index it once into a pyramid of tiles, then draw only what the camera shows, at the density the zoom allows. A reader opens a four-million-point chart with a {{size:galaxy}} bundle, streams the parts they look at from a static file, and every camera tour runs at 59–60 fps in Chrome. And when a million dots would only paint over each other, the standard library draws what they add up to — hexagons, grid cells, the contours of a crowd, a thousand series at once — binned in one pass by the engine.

// Rows the engine generates: four million stars from a seed, as expressions over the row number.
data: { stars: data.generate(4_000_000, {
  part: e(`rand(d.i, 1) < 0.14 ? 0 : …`),           // bar, halo, clusters, disk, arms
  r: e(`… -9500 * log(1 - rand(d.i, 3) * …)`),       // an exponential disk
  theta: e(`log(d.r / 5200) / 0.3 + … + randn(d.i, 4) * …`), // logarithmic arms
  x: e(`round(d.r * cos(d.theta), 2)`), y: e(`round(d.r * sin(d.theta), 2)`),
  temp: e(`…`), lum: e(`…`),                          // main-sequence stars and red giants
}, { keep: ["x", "y", "temp", "lum"] }) },

// Dots at their own x/y in an explorable view: level of detail, a glow, a tooltip each.
scene: cloud({ data: "stars", x: "x", y: "y", maxZoom: 3000,
  points: 80_000, glow: 6, glowOpacity: e("clamp(0.03 + 0.03 * d.lum, 0.015, 0.2)"),
  r: e("clamp(0.95 + 0.34 * d.lum, 0.75, 3.6)"), fill: e(`d.temp < 3700 ? "#ffb06e" : …`),

What they add up to

A million rows as a density, a shape, a crowd of lines

Past a few thousand dots a scatter is ink: you see where the marks are, not how many rows are there. Four recipes draw the rows as what they add up to. The engine bins them in one pass, in Rust, and keeps the result — every step, layout pass and hover reuses it — so a frame draws a few thousand bins, not hundreds of thousands of rows. The rows behind each chart below are generated from a seed, not downloaded: each chart is a bundle of {{size:std-contours}} to {{size:std-manylines}}, gzipped.

How it stays fast

Decisions that keep frames cheap

Point pyramids

An instances node with lod — or the cloud recipe — indexes a table of any size once into a quadtree whose levels are seeded, density-preserving samples. Each frame draws the levels whose rows in view fit its budget of points; up close, every row.

Streamed from a static file

The publish step writes the pyramid as a point archive (PMTiles of compact point tiles) next to the chart. The page reads it by HTTP range request from any static host — the galaxy's first view needs a few hundred kilobytes of its {{archive:galaxy}}.

Instanced marks

A scatter's points are one instanced draw, not thousands of shapes. The point recipe scales to 10⁵–10⁶ rows; a bar that splits into dots stays one instanced layer through the whole morph.

Plans, not per-frame work

When the state changes, the engine plans the transition once; a frame just evaluates the plan. Nothing user-written runs per frame — expressions are compiled bytecode — so animation frames cost fractions of a millisecond for most charts.

Prepared ahead, rendered on demand

While the reader reads, the engine prepares the next steps and warms their tiles, so handling a step takes a millisecond or less when the reader gets there. Nothing is drawn while nothing moves, and charts off screen sleep — battery matters on phones.

Binned in the engine

hexbin, heatmap2d and contours are table operations in Rust that read nothing but the rows: computed in one pass, once per data, and kept across states and hovers. The marks draw the bins, and the bins are sized in screen px, so a phone gets as many as it can show.

Generated data

Synthetic data too big to write down — simulations, load tests, procedural worlds — is a few expressions: data.generate(4_000_000, { … }) with seeded rand and randn, identical on every platform.

Instanced

20,000 points, recoloured in one step

Twenty thousand seeded points in three clusters. Step forward: every point resizes and recolours in one planned transition — about a third of a millisecond per animation frame in the engine.
