Extendable

Recipes are code you can open: eject one, or draw your own

The engine doesn't know what a bar chart is. It knows primitives — keyed shapes, text, instances, tiles, scales, coordinates, cameras — and the standard library builds every chart, axis, legend and basemap from them with the same public API you use. When the catalogue runs out there's no wall: copy a recipe and change it, or write one. Whatever you draw still morphs by key, reads out to screen readers and plays on every platform. Below, the engine's own recipe sandbox runs in your browser: edit the code and the chart follows.

What runs in this page

        
    
          
  • The engine's QuickJS sandbox, compiled into its WebAssembly: your module is a package of the document (packages: [{ name, source }], as the CLI embeds it), handed over with view.setDocument().
    • 
          
  • Expansion, with the engine's deterministic maths and its text measurement; no clock, no randomness, no network.
    • 
          
  • Errors with their line, a misspelt setting with “did you mean”, an endless loop stopped by the sandbox's time budget — try while (true) {}.
    • 
          
  • The morph to the standard chart: your marks pair with its marks by key.
    • 
        

      

      

        
What needs the CLI

        
    
          
  • TypeScript. This editor runs the JavaScript a document embeds; in a project you edit recipes/*.ts, and datars dev, check and publish compile it with esbuild (your editor's TypeScript checks the types).
    • 
          
  • datars eject std/<recipe>, which writes the standard source into your project.
    • 
          
  • datars lint, film, render, and publish — which expands recipes ahead of time, so readers' devices play the chart without running any recipe code.

The control ladder

      
Take as much control as you need — and no more

      
Each step down the ladder keeps every guarantee: determinism, seekable motion, accessibility, every platform.

    

    
    
      
  1. Use a recipe with parameters. bar({ labels: true, format: ",.0f", suffix: " kr" }) — {{count:recipes}} to choose from.
    2. 
      
  2. Override motion and style with motion rules and theme tokens — no change to the recipe.
    3. 
      
  3. Compose recipes. A plot with bars, a target rule and a callout is a few lines; so is your own “ranked bars with a highlight” recipe that wraps them.
    4. 
      
  4. Eject a recipe — datars eject std/bar copies its TypeScript into recipes/; import it from there and change anything. Unedited, it draws exactly what the standard one draws.
    5. 
      
  5. Write a recipe from primitives — shapes, text, instances, repeats, views with cameras, tiles — like the globe above.

Keys decide what becomes what

        
The workbench's charts pair with the standard ones by key alone. The bubbles are keyed by channel, as pie keys its slices, so each becomes its slice. The isotype's dots are keyed (channel, unit i): the engine sees each bar as the parent of its row's dots and gathers them into it — or splits it back out. One gap, plainly: units don't pair with another recipe's units (dots into a waffle's squares crossfade); they split from and gather into whole rows.


// recipes/isotype.ts: a row per unit, keyed (category, unit)
const units = cx.table("units", p.data, op.units({ value: p.value, as: "i" }));
instances({ key: "dots", from: units, x: e(`112 + (d.i + 0.5) * ${step}`), … })

      

      

        
Motion comes with it

        
Custom scenes get the same planner as the built-in charts: give marks keys and they morph between states; add rules for routes, staggers and ripples; give a recipe its own motion defaults — the way line draws on and bar grows from its baseline.


recipe({
  id: "@local/lollipop/lollipop",
  params: { data: t.table(), x: t.field(), y: t.field() },
  expand(p, cx) { /* keyed shapes */ },
  // Entering stems draw on from their base.
  motion: [{ select: { kind: "segment" }, enter: { trim: 0 } }],
});

      

    

  






  

    

      
Why it holds up

      
Custom code, the same guarantees

    

    

      
Dogfooded
The standard library is written with exactly this API — no private hooks. When a standard recipe needs something the SDK can't express, the SDK gets it, for everyone.

      
Nothing runs per frame
A recipe runs once per set of parameters and returns a scene with expressions; frames are the engine's compiled work. Your code can't make an animation stutter.

      
Deterministic sandbox
Recipes that must run on the device run in the engine's QuickJS sandbox with the engine's own maths — the same bits on every platform, no clock, no randomness without a seed, no network. Most bundles pre-expand them, so apps can refuse downloaded script and still play.

      
Measured text
cx.measure() asks the engine's shaper how wide a label will be — identical on every platform — so your layout decisions hold everywhere.

      
Themed
cx.ink("accent") and cx.token("size.label") return late-bound tokens, so your recipe follows the brand and dark mode like the built-ins.

      
Describable
Typed parameters become documentation, datars describe output and the descriptions agents read — with “did you mean” for misspelt parameters.
