Interactive

Charts that answer back — without event-handling code

In datars, interaction is part of the document. A chart declares signals — a selected set of keys, a brushed range, a number — and binds intents like inspect, activate, brush, drag, pan and zoom to its marks. Tables filter on signals, marks read them in expressions, and the engine does the rest: hit-testing, gestures, tooltips, and a keyed transition every time something changes. Views link because signals are global — no glue.

Click a bar

Linked views from one signal

Click a region's bar: it toggles in the selected key set, the other bars recede, and the trend's table filters to the selection — its lines morph as series come and go. Click again to clear.

signals: { selected: signal.keyset() },
tables: {
  trend: { from: "sales", ops: [
    op.filter(e("selected.isEmpty() || selected.has(d.region)")),
  ] },
},
scene: group({ layout: { type: "columns" }, children: [
  plot({ data: "totals", x: "region", y: "total", color: "region",
    children: [bar({ selected: "selected" })] }),   // click toggles the key set
  plot({ data: "trend", x: "month", y: "sales", color: "region",
    children: [line({ points: true })] }),
] }),

Brush and zoom

Brushing the overview writes a range signal; the detail's table keeps the rows inside it and a text mark shows the mean. A click clears the brush.

signals: { range: signal.range() },
tables: { detail: { from: "prices", ops: [op.filter(brushed("range", "d.day"))] } },
// …
plot({ data: "prices", x: "day", y: "price", xType: "linear", brush: "range",
  children: [area({ opacity: 0.3 }), line({ width: 1 })] }),

Try every control

Engine-drawn controls

Sliders and ranges, segmented choices, dropdowns, switches, checkboxes and buttons are part of the chart, drawn by the engine: identical on the web, in apps and in a video export, as quick as a UI, and offered to keyboards and screen readers as native controls. Each sets a signal the bars read.

segmented({ signal: "quarter", options: ["q1", "q2"], labels: ["Q1", "Q2"] }),
select({ signal: "region", options: regions, label: "Highlight" }),
toggle({ signal: "average", label: "Average line" }),
checklist({ signal: "shown", options: regions }),
range({ lo: "lo", hi: "hi", min: 0, max: 50 }),
button({ label: "Show every region", set: "shown", value: regions }),

The vocabulary

Signals, intents and actions

Everything interactive on this site is built from these — declared in the document, so it travels with the chart to every platform.

Signals

signal.num, str, bool, key, keyset, range — and clock, which counts up while a settled scene reads it (the spinning globe on the home page). Story steps set them; marks, tables and cameras read them.

Intents

inspect (hover, tap, focus), activate (click, tap, Enter, a screen reader's double-tap), brush, drag, pan and zoom. Documents bind intents, not mouse events, so the same chart works with every input.

Actions

Set a signal, toggle a key in a set, brush a range, scrub a value along a scale, fire an event for the host, or enter a drill-down chapter with the clicked key — all data, no callbacks.

Tooltips

Every data mark has a label — “Sweden Democrats: 20.5” — shown on inspect, drawn by the engine so it's the same on every platform, and read by screen readers.

Explorable views

A view's camera can name signals that drag and wheel or pinch move, between a minimum and a maximum zoom. The four-million-star galaxy is one; stepping a story flies the camera back into the narrative.

Drill-down

A bar can enter a program chapter with its category when clicked — a sub-story about that one key — and the back event leaves it.

Text

Chart text you can select, copy and find

A chart's titles, labels and annotations are drawn by the engine, and on the web they're also laid out as real text over the canvas, glyph for glyph: drag to select a title and copy it, find a label with Ctrl+F, and search engines read it. Hover, clicks on marks and panning a map work as before — a drag on a label only selects when it's a text drag.

Talk to the page or the app

Host and chart, both ways

The page or app can drive the chart — set a signal from your own filter, jump to a state, hand in data — and listen to it: the state event reports the step, its narration and the chart's semantics.

  • Web: setSignal(name, value), send("goto:ranked"), data = { slot: rows }, the state event.
  • iOS: DatarsChart(source:state:) follows SwiftUI state; the engine's setSignal sets numeric signals.
  • Android: send("next"), goTo(index), provideData(…).

const chart = document.querySelector("datars-view");

// The page drives the chart…
myRegionFilter.addEventListener("change", (e) =>
  chart.setSignal("region", e.target.value));

// …and follows it.
chart.addEventListener("state", (e) => {
  const { state, narration } = e.detail;
  caption.textContent = narration?.text ?? "";
});
